# ios-app/ — Capacitor wrap of Tokutei Kensetsu (iOS)

This folder lives INSIDE the web app repo (donghung94/1). The web app stays
at the repo root, untouched; everything Capacitor-related is in here.

## Layout

```
<repo root>/                    LIVE WEB APP (GitHub Pages: donghung94.github.io/1)
  index.html, premium.html, tu-vung.html, exam.html, ...   <- web source
  demo-sora/                    test build (NOT synced into the app)
  service-worker.js             web only (NOT synced into the app)
  ios-app/                      THIS FOLDER — Capacitor project root
    package.json / package-lock.json
    capacitor.config.ts         appId com.donghung.tokuteikensetsu, webDir www
    sync-web.js                 copies the web app (repo root) into www/
    www/                        GENERATED by sync-web.js — gitignored
    ios/
      App/
        App.xcworkspace         <- Xcode Cloud builds THIS workspace
        App.xcodeproj
        App/public/             GENERATED by `cap sync` — gitignored
        ci_scripts/ci_post_clone.sh
```

## How the build works (Xcode Cloud)

1. App Store Connect → Tokutei Kensetsu → Xcode Cloud workflow points at
   workspace **ios-app/ios/App/App.xcworkspace**, scheme **App**.
2. On every clone, Xcode Cloud runs **ios/App/ci_scripts/ci_post_clone.sh**:
   installs Node via Homebrew if missing → `cd ios-app/` → `npm install` →
   `node sync-web.js` (regenerates `www/` from the repo root — the web app
   is always whatever is committed at the repo root, nothing extra to
   maintain) → `npx cap sync ios`.
3. **Signing is Apple-managed in Xcode Cloud** (automatic signing, team
   X648TYLRMX) — no App Store Connect API key (.p8) lives in repo secrets
   for this route.
4. Bundle ID is `com.donghung.tokuteikensetsu` — set in capacitor.config.ts
   and verified in ios/App/App.xcodeproj/project.pbxproj
   (PRODUCT_BUNDLE_IDENTIFIER, Debug + Release).

## sync-web.js

- Source defaults to the PARENT of ios-app/ (the repo root). Override for
  local testing with the `WEB_SRC` env var:
  `WEB_SRC=/path/to/repo-mirror node sync-web.js`
- Skips: `ios-app/` itself (no recursion), `demo-sora/`,
  `service-worker.js` (the native shell must not register the web SW),
  `.git/`, `node_modules/`.
- `guide/` images ARE included (needed by dang-ky.html).

## ⚠️ TypeScript pin

`typescript` is pinned to **^5.x** in devDependencies — do NOT upgrade to
TS 7: `@capacitor/cli` 6 fails on TS 7 with
`TypeError: Cannot read properties of undefined (reading 'CommonJS')`
when parsing capacitor.config.ts. (Hit and fixed 2026-11-25.)

## Still open before submission — native sign-in wiring

- **Apple/Google sign-in does NOT work as-is inside the WKWebView shell:**
  the web OAuth popup/redirect flows (Firebase `signInWithPopup` /
  `signInWithRedirect`) break in WKWebView. Before submission, wire the
  native flows — native Sign in with Apple + native Google sign-in →
  Firebase `signInWithCredential` — and test on a real device build.
  Do not ship the raw web OAuth redirects inside the shell.
- IAP: product `com.donghung.tokuteikensetsu.premium.lifetime`
  (already created in App Store Connect at ₫499,000). Purchase completion
  must set `users/{uid}.isPremium = true`, `premiumUntil = null`
  (server-verified receipt → the same two fields the VietQR webhook
  writes). Inside Capacitor, premium.html already hides the VietQR flow
  and shows the IAP note only; the web keeps VietQR. Premium state lives
  on the account, so web and app stay in sync.

## Local commands (run from ios-app/)

- `npm run sync-web` — refresh `www/` from the repo root
- `npm run build-ios` — sync-web + `npx cap sync ios`
